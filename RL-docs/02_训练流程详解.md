## ROLL 训练流程详解

### 一、训练流程总览

ROLL 支持多种训练流水线，每种流水线都遵循相似的生命周期模式。以最核心的 **RLVR Pipeline** 为例，一个完整的训练 step 包含以下阶段：

```
┌──────────────────────────────────────────────────────────────────┐
│                     RLVR 单步训练流程                              │
│                                                                  │
│  1. Model Update    ──→  将 Actor Train 的最新权重同步到 Actor Infer │
│  2. Rollout         ──→  Actor Infer 生成 response                │
│  3. Reward          ──→  多种 Reward Worker 并行计算奖励            │
│  4. Reference       ──→  Reference 模型计算 ref_log_probs          │
│  5. Advantage       ──→  计算优势函数 (GAE / Reinforce / GRPO)     │
│  6. Train           ──→  Actor Train 执行策略梯度更新               │
│  7. Checkpoint      ──→  按步数保存检查点                           │
│  8. Validation      ──→  按步数执行验证集评估                       │
└──────────────────────────────────────────────────────────────────┘
```

### 二、RLVR Pipeline 详解

RLVR（Reinforcement Learning with Verifiable Rewards）是 ROLL 最核心的训练流水线，适用于数学推理、代码生成、通用推理等可验证任务。

#### 2.1 初始化阶段

```python
class RLVRPipeline(BasePipeline):
    def __init__(self, pipeline_config: RLVRConfig):
        # 1. 创建 Cluster（角色集群）
        self.actor_train = Cluster(name="actor_train", ...)   # 训练集群
        self.actor_infer = Cluster(name="actor_infer", ...)   # 推理集群
        self.reference = Cluster(name="reference", ...)       # 参考模型集群

        # 2. 创建 Reward Worker（可以有多个不同类型）
        self.reward_workers = {
            "math_rule": MathRuleRewardWorker,
            "code_sandbox": CodeSandboxRewardWorker,
            "llm_judge": LLMJudgeRewardWorker,
            ...
        }

        # 3. 初始化各集群
        self.actor_train.initialize(pipeline_config)
        self.actor_infer.initialize(pipeline_config)
        self.reference.initialize(pipeline_config)

        # 4. 设置模型同步对
        self.set_model_update_pair(
            src_cluster=self.actor_train,
            tgt_cluster=self.actor_infer,
            frequency=1  # 每步同步
        )

        # 5. 创建 GenerateScheduler（异步生成调度器）
        self.generate_scheduler = GenerateScheduler.remote()

        # 6. 加载数据集
        self.dataset = get_dataset(data_args)
```

#### 2.2 数据准备

ROLL 支持**多任务混合训练**，通过 `domain_interleave_probs` 控制各任务的采样比例：

```yaml
data_args:
  file_name:
    - data/code_KodCode_data.jsonl        # 代码任务
    - data/math_deepmath_deal.jsonl        # 数学任务
    - data/general_ifeval_train_deal.jsonl  # 指令遵循
  domain_interleave_probs:
    math_rule: 0.4      # 40% 数学
    code_sandbox: 0.3    # 30% 代码
    llm_judge: 0.1       # 10% LLM 评判
    crossthinkqa: 0.1    # 10% 跨领域QA
    ifeval: 0.1          # 10% 指令遵循
```

数据处理流程：
1. **加载**: 从 jsonl/parquet 文件加载数据集
2. **模板化**: 使用 `chat_template` 将原始数据转换为模型输入格式
3. **Tokenize**: 分词并 padding 到 `prompt_length`
4. **Collate**: `DataCollatorWithPadding` 将样本组装为 batch
5. **Tag 标记**: 每条数据携带 `tag` 标识其所属任务域

#### 2.3 Rollout 阶段（生成）

Rollout 是 RL 训练中最耗时的阶段，ROLL 提供了多层次的优化：

##### 同步 Rollout（generate_opt_level=0）
```
Pipeline → Cluster.generate(batch) → 所有 DP Worker 同步生成 → 收集结果
```

##### 异步 Rollout（generate_opt_level=1）
```
Pipeline → GenerateScheduler
              ├── 逐条分发请求到各 DP Worker（负载均衡）
              ├── Worker 使用 vLLM/SGLang 的 continuous batching
              ├── 完成的请求立即回调
              └── 所有请求完成后返回
```

**负载均衡策略**: GenerateScheduler 维护每个 DP Worker 的当前负载（`load_balance_coordinator`），每次选择负载最小的 Worker 分发新请求。

**num_return_sequences 展开**: 当 `is_num_return_sequences_expand=True` 时，每个 prompt 会被复制 N 份独立生成，而非一次生成 N 个序列。这在某些场景下可以提高生成多样性。

##### 生成后处理
```python
def postprocess_generate(data: DataProto):
    # 1. 拼接 prompt + response
    concatenate_input_and_output(data)
    # 2. 构建 response_mask（标记哪些 token 是 response）
    # 3. 截断到 sequence_length
    # 4. 记录生成长度等统计信息
```

#### 2.4 Reward 计算

ROLL 支持多种 Reward 类型，通过 `tag` 将数据路由到对应的 Reward Worker：

| Reward 类型 | Worker 类 | 适用场景 |
|-------------|-----------|---------|
| **Math Rule** | `MathRuleRewardWorker` | 数学题答案验证（精确匹配） |
| **Code Sandbox** | `CodeSandboxRewardWorker` | 代码执行验证（沙箱运行） |
| **LLM Judge** | `LLMJudgeRewardWorker` | LLM 作为评判者（开放式问题） |
| **IFEval Rule** | `GeneralRuleRewardWorker` | 指令遵循规则验证 |
| **CrossThinkQA** | `CrossThinkQARuleRewardWorker` | 跨领域 QA 规则验证 |

**Reward 计算流程**:
```
1. RewardScheduler 按 tag 分发数据到对应 Reward Worker
2. 各 Reward Worker 并行计算奖励
3. 收集所有奖励结果，合并到 batch 中
4. 奖励后处理：
   - reward_clip: 裁剪奖励值到 [-clip, clip]
   - reward_normalization: 奖励标准化
   - token_level_kl: 添加 token 级别 KL 惩罚
```

**动态过滤（Query Filter）**: ROLL 支持在 Reward 计算后对数据进行动态过滤：
- `mean_filter`: 过滤掉正确率过高或过低的 prompt
- `std_filter`: 过滤掉标准差为 0 的 prompt（所有 response 得分相同）

#### 2.5 Advantage 计算

优势函数（Advantage）是 RL 训练的核心，ROLL 支持多种估计方法：

| 方法 | 配置值 | 公式 | 适用场景 |
|------|--------|------|---------|
| **GAE** | `gae` | \(A_t = \sum_{l=0}^{T-t} (\gamma\lambda)^l \delta_{t+l}\) | PPO（需要 Critic） |
| **Reinforce** | `reinforce` | \(A_i = R_i - \text{baseline}\) | Reinforce++（无 Critic） |
| **GRPO** | `grpo` | \(A_i = \frac{R_i - \text{mean}(R)}{\text{std}(R)}\) | Group 内标准化 |
| **RLOO** | `rloo` | \(A_i = R_i - \frac{1}{K-1}\sum_{j \neq i} R_j\) | Leave-one-out 基线 |

**Advantage 白化（Whiten）**: 当 `whiten_advantages=True` 时，对 advantage 进行标准化处理，稳定训练。

**样本级别掩码**:
- `max_len_mask`: 过滤达到最大长度的样本（可能是截断的不完整回答）
- `difficulty_mask`: 过滤过于简单或过于困难的 prompt
  - `difficulty_low_threshold`: 正确率下限（默认 0.1）
  - `difficulty_high_threshold`: 正确率上限（默认 0.95）

#### 2.6 策略梯度训练

训练阶段执行策略梯度更新，核心损失函数：

##### PPO/GRPO 损失
```python
# 计算 ratio
ratio = exp(log_probs - old_log_probs)

# PPO Clip 损失
surr1 = ratio * advantages
surr2 = clamp(ratio, 1-epsilon, 1+epsilon) * advantages
policy_loss = -min(surr1, surr2)

# Dual Clip（可选）
if dual_clip_loss:
    surr3 = max(policy_loss, dual_clip_coef * advantages)
    policy_loss = where(advantages < 0, surr3, policy_loss)
```

##### 损失聚合模式（`loss_agg_mode`）
- `token-mean`: 所有 token 的平均损失
- `seq-mean-token-sum`: 先对每个序列求 token 和，再对序列求平均
- `seq-mean-token-mean`: 先对每个序列求 token 平均，再对序列求平均

##### KL 惩罚
```python
# Token-level KL
kl = log_probs - ref_log_probs
token_reward = -kl_coef * kl

# Adaptive KL Controller
kl_ctrl.update(current_kl, target_kl)  # 动态调整 kl_coef
```

#### 2.7 模型同步（Model Update）

训练完成后，需要将 Actor Train 的最新权重同步到 Actor Infer：

```
ModelUpdateGroup.model_update(global_step):
    1. 检查是否到达同步频率 (global_step % frequency == 0)
    2. 建立 NCCL 通信组（src_cluster ↔ tgt_cluster）
    3. 按 PP stage 逐层广播参数
    4. 支持 bucket 模式批量传输，减少通信次数
```

**同步方式**:
- `nccl`: 通过 NCCL 集合通信广播参数（默认，高效）
- `rpc`: 通过 Ray RPC 传输参数（仅用于 RTP 后端）

### 三、Agentic Pipeline 详解

Agentic Pipeline 用于多轮交互的 Agent RL 训练，与 RLVR 的主要区别在于 **Rollout 阶段**。

#### 3.1 多轮交互 Rollout

```
┌─────────────────────────────────────────────────────┐
│                 Agentic Rollout 流程                  │
│                                                     │
│  RolloutScheduler                                   │
│  ├── GroupQueueManager (管理环境组)                    │
│  ├── EnvironmentWorker (环境执行器)                    │
│  └── EnvManager (环境管理器)                          │
│                                                     │
│  循环:                                               │
│    1. Agent 生成 action (Actor Infer)                │
│    2. 环境执行 action，返回 observation + reward       │
│    3. 拼接 observation 到 context                    │
│    4. 重复直到 done 或达到最大轮次                      │
│    5. 收集完整 trajectory                            │
└─────────────────────────────────────────────────────┘
```

#### 3.2 环境管理器（EnvManager）

ROLL 提供多种环境管理器，适配不同的训练范式：

| 管理器 | 文件 | 训练范式 |
|--------|------|---------|
| **TrajEnvManager** | `traj_env_manager.py` | TrajectoryWise（StarPO）：整条轨迹一个奖励 |
| **StepEnvManager** | `step_env_manager.py` | StepWise（GiGPO）：每步一个奖励 |
| **StepConcatEnvManager** | `step_concat_env_manager.py` | StepWise 拼接模式 |
| **TIREnvManager** | `tir_env_manager.py` | Tool-Integrated Reasoning |
| **VLTrajEnvManager** | `vl_traj_env_manager.py` | 视觉语言模型的轨迹管理 |

#### 3.3 异步训练

Agentic Pipeline 支持**异步训练**（`async_generation_ratio > 0`）：
- 训练和 rollout 可以并行执行
- 使用 `async_generation_ratio` 控制预生成的 episode 数量
- 训练使用当前步的数据，同时预生成下一步的数据

### 四、Distill Pipeline 详解

知识蒸馏 Pipeline 将 Teacher 模型的知识迁移到 Student 模型。

#### 4.1 训练流程

```
1. 数据预处理: 对话数据 → tokenize → labels 构建
2. Teacher Forward: Teacher 模型计算 logits
3. Logits 传输: 通过 LogitsTransferGroup 将 Teacher logits 传给 Student
4. Student Train: Student 使用 KL 散度损失学习 Teacher 的输出分布
5. 循环直到收敛
```

#### 4.2 关键特性

- **LogitsTransferGroup**: 通过 NCCL 在 Teacher 和 Student 之间高效传输 logits
- **Top-K Distill**: 只传输 top-k 的 logits，减少通信量
- **Temperature Scaling**: 使用温度参数控制蒸馏强度
- **Distill on Prompt**: 可选择是否在 prompt 部分也进行蒸馏

---

### 五、DPO Pipeline

Direct Preference Optimization 直接从偏好数据学习，无需显式奖励模型。

```
1. 加载偏好数据 (chosen/rejected pairs)
2. 计算 chosen 和 rejected 的 log_probs
3. 计算 reference 模型的 log_probs
4. DPO 损失: L = -log(σ(β * (log π(y_w|x)/π_ref(y_w|x) - log π(y_l|x)/π_ref(y_l|x))))
5. 梯度更新
```

---

### 六、SFT Pipeline

监督微调 Pipeline，使用标准的交叉熵损失进行训练。

```
1. 加载指令微调数据
2. 构建 labels（prompt 部分设为 IGNORE_INDEX）
3. 前向传播计算 language modeling loss
4. 梯度更新
```

### 七、训练生命周期管理

#### 7.1 检查点保存与恢复

```python
# 保存
def do_checkpoint(global_step):
    # 1. 各 Cluster 保存模型权重
    cluster.do_checkpoint(global_step)
    # 2. 保存 Pipeline 状态（step, log_history, rng_state）
    state.save_to_json(save_dir)
    # 3. 上传到远程存储（可选）
    checkpoint_manager.upload(ckpt_id, local_path)

# 恢复
if resume_from_checkpoint:
    state = WorkerState.load_from_json(load_dir)
    # 跳过已完成的 step
    for global_step in range(max_steps):
        if global_step <= state.step:
            continue
```

#### 7.2 指标追踪

ROLL 集成了多种追踪后端：
- **TensorBoard**: 默认追踪器
- **WandB**: Weights & Biases
- **SwanLab**: 国产追踪平台
- **stdout**: 标准输出

追踪的关键指标：
```
# 训练指标
train/policy_loss          # 策略损失
train/value_loss           # 价值损失（PPO）
train/entropy              # 策略熵
train/kl                   # KL 散度
train/clip_fraction        # PPO clip 比例

# 奖励指标（按 domain 分组）
reward/{domain}/mean       # 各任务域的平均奖励
reward/{domain}/accuracy   # 各任务域的正确率

# 系统指标
time/step_rollout          # Rollout 耗时
time/step_train            # 训练耗时
time/step_model_update     # 模型同步耗时
system/tokens_per_second   # 系统吞吐量
```

#### 7.3 Offload/Reload 机制

当 Actor Train 和 Actor Infer 共享 GPU 时，ROLL 通过状态 offload 实现时分复用：

```
训练阶段:
  Actor Infer → offload_states() → CPU/磁盘
  Actor Train → load_states() → GPU
  执行训练...

推理阶段:
  Actor Train → offload_states() → CPU/磁盘
  Actor Infer → load_states() → GPU
  执行推理...
```

支持的 offload 类型（`OffloadStateType`）:
- `model_params`: 模型参数
- `optimizer_states`: 优化器状态
- `grad_buffers`: 梯度缓冲区
