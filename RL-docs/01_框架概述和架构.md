## ROLL 框架概述与架构

### 一、项目定位

**ROLL**（Reinforcement Learning Optimization for Large-Scale Learning）是阿里巴巴淘天集团与阿里 AI 引擎团队联合开发的**大模型强化学习训练框架**，专注于 LLM/VLM 的后训练（Post-Training）阶段。其核心目标是提供一个**高效、用户友好、可扩展**的 RL 训练系统，支持从单机到千卡集群的无缝扩展。

**论文**: [arXiv:2506.06122](https://arxiv.org/abs/2506.06122)

**核心价值主张**:
- 统一多种后训练范式（RLVR / Agentic RL / Distill / DPO / SFT）
- 丰富的 RL 算法库（PPO、GRPO、Reinforce++、TOPR、GSPO 等 10+ 种）
- 灵活的训练/推理后端组合（Megatron + vLLM / SGLang）
- 基于 Ray 的分布式多角色架构，支持 colocated 和 disaggregated 部署

---

### 二、整体架构总览

ROLL 的架构可以从**四个层次**来理解：

```
┌─────────────────────────────────────────────────────────┐
│                    Pipeline Layer                        │
│  (RLVRPipeline / AgenticPipeline / DistillPipeline ...)  │
├─────────────────────────────────────────────────────────┤
│                   Scheduler Layer                        │
│  (GenerateScheduler / RolloutScheduler / RewardScheduler)│
├─────────────────────────────────────────────────────────┤
│                   Executor Layer                         │
│  (Cluster → Worker → Strategy)                           │
│  基于 Ray Actor 的分布式执行引擎                           │
├─────────────────────────────────────────────────────────┤
│                   Backend Layer                           │
│  训练: DeepSpeed ZeRO / Megatron 5D并行 / FSDP            │
│  推理: vLLM / SGLang / HF / RTP                          │
└─────────────────────────────────────────────────────────┘
```

### 三、核心模块详解

#### 3.1 Pipeline Layer（流水线层）

Pipeline 是 ROLL 的最顶层抽象，定义了一个完整的训练流程。所有 Pipeline 继承自 `BasePipeline`（`roll/pipeline/base_pipeline.py`）。

| Pipeline | 文件路径 | 用途 |
|----------|---------|------|
| **RLVRPipeline** | `roll/pipeline/rlvr/` | 基于规则验证的强化学习（数学、代码、通用推理） |
| **RLVR VLM Pipeline** | `roll/pipeline/rlvr/rlvr_vlm_pipeline.py` | 视觉语言模型的 RLVR 训练 |
| **AgenticPipeline** | `roll/pipeline/agentic/agentic_pipeline.py` | 多轮交互的 Agent RL 训练（游戏、工具使用） |
| **DistillPipeline** | `roll/pipeline/distill/distill_pipeline.py` | 知识蒸馏（Teacher → Student） |
| **DPO Pipeline** | `roll/pipeline/dpo/` | Direct Preference Optimization |
| **SFT Pipeline** | `roll/pipeline/sft/` | 监督微调 |
| **RewardFL Pipeline** | `roll/pipeline/diffusion/reward_fl/` | 扩散模型的 Reward Fine-tuning |

**BasePipeline 核心职责**:
```python
class BasePipeline:
    def __init__(self, pipeline_config):
        self.resource_manager = ResourceManager(...)   # GPU 资源管理
        self.state = WorkerState()                      # 训练状态管理
        self.checkpoint_manager = CheckpointManager(...) # 检查点管理
        self.tracker = create_tracker(...)              # 指标追踪

    def set_model_update_pair(self, src, tgt, frequency)  # 设置模型同步对
    def model_update(self, global_step)                    # 执行模型参数同步
    def do_checkpoint(self, global_step)                   # 保存检查点
    def download_models(self, *clusters)                   # 分布式模型下载
```

#### 3.2 Executor Layer（执行层）

执行层是 ROLL 分布式架构的核心，由三个关键组件组成：

##### 3.2.1 Worker（`roll/distributed/executor/worker.py`）

Worker 是最基本的执行单元，每个 Worker 是一个 **Ray Actor**，运行在指定的 GPU 上。

```
Worker 核心属性:
├── worker_config: WorkerConfig    # 配置信息
├── strategy: Strategy             # 训练/推理策略
├── rank_info: RankInfo            # 分布式拓扑信息 (dp/tp/pp/cp rank)
├── shared_storage: SharedStorage  # Ray 共享存储
└── cluster_name / worker_name     # 身份标识
```

**RankInfo** 记录了 Worker 在分布式拓扑中的位置：
- `dp_rank` / `dp_size`: 数据并行维度
- `tp_rank` / `tp_size`: 张量并行维度
- `pp_rank` / `pp_size`: 流水线并行维度
- `cp_rank` / `cp_size`: 上下文并行维度

##### 3.2.2 Cluster（`roll/distributed/executor/cluster.py`）

Cluster 管理一组 Worker，是 Pipeline 与 Worker 之间的桥梁。

```
Cluster 核心功能:
├── _create_workers()       # 创建 Ray Actor，分配 PlacementGroup
├── _bind_worker_method()   # 魔法方法：将 Worker 方法绑定到 Cluster 上
├── execute_all_sync()      # 同步执行所有 Worker
├── execute_all_async()     # 异步执行所有 Worker
└── execute_rank_zero()     # 仅在 rank 0 执行
```

**关键设计**: Cluster 通过 `_bind_worker_method()` 实现了**方法代理模式**——Worker 上标记了 `@register(dispatch_mode=...)` 的方法会被自动绑定到 Cluster 上，Pipeline 可以直接调用 `cluster.generate(data)` 而无需关心底层的分发逻辑。

分发模式（Dispatch Mode）:
- `ONE_TO_ALL`: 广播到所有 Worker
- `DP_MP_COMPUTE`: 按数据并行维度分发，模型并行维度内复制
- `MEGATRON_PP_COMPUTE`: Megatron 流水线并行分发

##### 3.2.3 Strategy（`roll/distributed/strategy/`）

Strategy 是训练/推理后端的抽象层，将不同的底层引擎统一为相同的接口。

```
Strategy 继承体系:
InferenceStrategy (ABC)
├── HfInferStrategy          # HuggingFace 原生推理
├── VllmStrategy             # vLLM 推理引擎
├── SgLangStrategy           # SGLang 推理引擎
├── MegatronInferStrategy    # Megatron 推理
├── RtpStrategy              # RTP 推理
└── MockInferStrategy        # 测试用 Mock

TrainStrategy (InferenceStrategy)
├── DeepSpeedTrainStrategy   # DeepSpeed ZeRO 训练
├── MegatronTrainStrategy    # Megatron 5D 并行训练
└── FSDPTrainStrategy        # FSDP 训练 (开发中)
```

**Strategy 工厂**（`roll/distributed/strategy/factory.py`）通过 `strategy_name` 延迟导入对应的策略类，避免 CUDA 提前初始化：
```python
def create_strategy(worker):
    strategy_name = worker.worker_config.strategy_args.strategy_name
    if strategy_name == "vllm":
        from roll.distributed.strategy.vllm_strategy import VllmStrategy
        return VllmStrategy(worker)
    elif strategy_name == "megatron_train":
        from roll.distributed.strategy.megatron_strategy import MegatronTrainStrategy
        return MegatronTrainStrategy(worker)
    # ...
```

#### 3.3 Scheduler Layer（调度层）

调度层负责协调数据流和异步操作：

| 调度器 | 文件 | 职责 |
|--------|------|------|
| **GenerateScheduler** | `generate_scheduler.py` | 管理推理请求的异步分发与负载均衡 |
| **RolloutScheduler** | `rollout_scheduler.py` | Agentic RL 的多轮交互 rollout 调度 |
| **RewardScheduler** | `reward_scheduler.py` | 奖励计算的异步调度 |
| **RequestScheduler** | `generate_scheduler.py` | 动态采样调度 |

**GenerateScheduler** 支持两种优化级别：
- **Level 0**: 基础批量生成，同步等待所有结果
- **Level 1**: 异步 + 负载均衡，逐条分发请求到各 DP Worker，实现 sample-level 异步并行

#### 3.4 数据传输协议 DataProto

`DataProto`（`roll/distributed/scheduler/protocol.py`）是 ROLL 中所有模块间数据交换的标准协议：

```python
@dataclass
class DataProto:
    batch: TensorDict = None          # 张量数据（input_ids, attention_mask 等）
    non_tensor_batch: Dict = {}       # 非张量数据（tag, ground_truth 等）
    meta_info: Dict = {}              # 元信息（metrics, generation_config 等）
```

**设计优势**:
- 基于 PyTorch TensorDict，支持像操作单个 Tensor 一样操作字典
- 支持切片、索引、拼接、padding 等操作
- 自定义序列化/反序列化，优化 Ray RPC 传输效率
- 统一了张量和非张量数据的管理

### 四、角色（Role）体系

ROLL 中的训练系统由多个**角色**组成，每个角色对应一个 Cluster：

| 角色 | 配置键 | 职责 | 典型 Strategy |
|------|--------|------|---------------|
| **Actor Train** | `actor_train` | 策略模型训练 | `megatron_train` / `deepspeed_train` |
| **Actor Infer** | `actor_infer` | 策略模型推理（Rollout 生成） | `vllm` / `sglang` |
| **Reference** | `reference` | 参考模型（计算 KL 散度） | `megatron_infer` |
| **Critic** | `critic` | 价值网络（PPO 中使用） | `deepspeed_train` |
| **Reward** | `rewards` | 奖励模型/规则奖励 | 自定义 Worker |

**GPU 时分复用**: 当 Actor Train 和 Actor Infer 共享 GPU（colocated 部署）时，ROLL 通过 **offload/reload 机制**实现 GPU 时分复用——训练时将推理模型 offload 到 CPU，推理时将训练模型 offload。

### 七、设计哲学

1. **策略抽象统一后端**: 通过 Strategy 层将 DeepSpeed、Megatron、vLLM、SGLang 等不同后端统一为相同接口，用户只需在 YAML 中切换 `strategy_name` 即可更换后端。

2. **Ray-based 多角色架构**: 每个角色（Actor/Critic/Reference/Reward）独立为 Ray Actor 集群，天然支持异构部署和弹性扩缩容。

3. **DataProto 统一数据流**: 所有模块间通过 DataProto 传递数据，避免了复杂的数据格式转换。

4. **配置驱动**: 通过 Hydra + dataclass 的配置系统，用户只需编写 YAML 文件即可定义完整的训练流程，无需修改代码。

5. **异步优先**: 从 sample-level 异步 rollout 到环境级异步 rollout，再到异步训练，ROLL 在各个层面追求最大化 GPU 利用率。
