## ROLL 分布式架构与算法

### 一、分布式架构总览

ROLL 采用 **Ray-based 多角色分布式架构**，将 RL 训练系统拆分为多个独立的角色（Role），每个角色由一个 Cluster 管理，Cluster 内部由多个 Worker（Ray Actor）组成。

```
┌─────────────────────────────────────────────────────────────┐
│                      Ray Cluster                             │
│                                                             │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐       │
│  │ Actor Train  │  │ Actor Infer  │  │  Reference   │       │
│  │  Cluster     │  │  Cluster     │  │  Cluster     │       │
│  │ ┌──┐┌──┐┌──┐│  │ ┌──┐┌──┐┌──┐│  │ ┌──┐┌──┐┌──┐│       │
│  │ │W0││W1││W2││  │ │W0││W1││W2││  │ │W0││W1││W2││       │
│  │ └──┘└──┘└──┘│  │ └──┘└──┘└──┘│  │ └──┘└──┘└──┘│       │
│  └──────────────┘  └──────────────┘  └──────────────┘       │
│                                                             │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐       │
│  │   Reward     │  │ Generate     │  │  Rollout     │       │
│  │  Workers     │  │ Scheduler    │  │ Scheduler    │       │
│  └──────────────┘  └──────────────┘  └──────────────┘       │
└─────────────────────────────────────────────────────────────┘
```

#### 2.2 AutoDeviceMapping

ROLL 支持灵活的设备映射配置，用户可以为不同角色指定不同的 GPU：

```yaml
# Colocated 部署（训练和推理共享 GPU）
actor_train:
  device_mapping: list(range(0,8))    # GPU 0-7
actor_infer:
  device_mapping: list(range(0,8))    # GPU 0-7（共享）

# Disaggregated 部署（训练和推理使用不同 GPU）
actor_train:
  device_mapping: list(range(0,16))   # GPU 0-15（训练专用）
actor_infer:
  device_mapping: list(range(0,12))   # GPU 0-11（推理专用）
reference:
  device_mapping: list(range(0,16))   # GPU 0-15（与训练共享）
```

**Colocated 检测**:
```python
def is_colocated(actor_train, actor_infer):
    train_devices = set(actor_train.device_mapping)
    infer_devices = set(actor_infer.device_mapping)
    return train_devices.issuperset(infer_devices)
```

当检测到 colocated 部署时，ROLL 自动启用 **offload/reload 机制**进行 GPU 时分复用。

### 三、训练后端

#### 3.1 DeepSpeed ZeRO（`roll/distributed/strategy/deepspeed_strategy.py`）

DeepSpeed ZeRO 是 ROLL 支持的轻量级训练后端，适合中小规模模型。

**支持的 ZeRO 阶段**:
| 阶段 | 分片内容 | 适用场景 |
|------|---------|---------|
| ZeRO-2 | 优化器状态 + 梯度 | 中等规模模型 |
| ZeRO-3 | 优化器状态 + 梯度 + 参数 | 大规模模型 |
| ZeRO-3 + CPU Offload | 同上 + CPU 卸载 | 显存受限场景 |

**配置示例**:
```yaml
actor_train:
  strategy_args:
    strategy_name: deepspeed_train
    strategy_config:
      zero_stage: 2
      offload_optimizer: false
```

#### 3.2 Megatron 5D 并行（`roll/distributed/strategy/megatron_strategy.py`）

Megatron 是 ROLL 的主力训练后端，支持 5 维并行：

| 并行维度 | 配置参数 | 说明 |
|---------|---------|------|
| **DP** (Data Parallel) | 自动计算 | 数据并行，每个 DP rank 处理不同数据 |
| **TP** (Tensor Parallel) | `tensor_model_parallel_size` | 张量并行，将模型层内的矩阵切分 |
| **PP** (Pipeline Parallel) | `pipeline_model_parallel_size` | 流水线并行，将模型层间切分 |
| **CP** (Context Parallel) | 通过 `ulysses_size` 配置 | 上下文并行，切分序列长度 |
| **EP** (Expert Parallel) | `expert_model_parallel_size` | 专家并行，用于 MoE 模型 |

**DP Size 自动计算**:
```python
dp_size = total_gpus / (tp_size * pp_size * ep_size)
```

**配置示例**:
```yaml
actor_train:
  strategy_args:
    strategy_name: megatron_train
    strategy_config:
      tensor_model_parallel_size: 2
      pipeline_model_parallel_size: 2
      expert_model_parallel_size: 1
      use_distributed_optimizer: true
      recompute_granularity: full    # 激活重计算
```

**mcore_adapter**（`mcore_adapter/`）是 ROLL 对 Megatron-LM 的适配层，提供：
- HuggingFace 模型到 Megatron 格式的自动转换
- 支持 Qwen2/2.5、Qwen3、Qwen3-MoE、LLaMA、DeepSeek-V3 等模型
- 分布式检查点保存/加载
- LoRA 适配器支持

#### 3.3 FSDP（开发中）

`roll/distributed/strategy/fsdp_strategy.py` — PyTorch 原生的 Fully Sharded Data Parallel，正在开发中。

### 四、推理后端

#### 4.1 vLLM（`roll/distributed/strategy/vllm_strategy.py`）

vLLM 是 ROLL 的主要推理后端，提供高效的 LLM 推理：

**核心特性**:

### 五、模型参数同步

#### 5.1 ModelUpdateGroup（`roll/distributed/executor/model_update_group.py`）

ModelUpdateGroup 管理训练集群到推理集群的参数同步：

```
同步流程:
1. 建立 NCCL 通信组
   - 为每个 PP stage 建立独立的通信组
   - src (Train Worker) 和 tgt (Infer Worker) 加入同一组
   
2. 参数广播
   方式一: 逐参数广播
     for param in model.parameters():
         broadcast(param, src=train_rank)
   
   方式二: Bucket 批量广播（更高效）
     将多个参数打包到 bucket 中
     broadcast(bucket, src=train_rank)
     
3. 通信组管理
   - setup_collective_group(): 初始化通信组
   - broadcast_parameter(): 单参数广播
   - broadcast_bucket(): 批量广播
```

**通信计划（Comm Plan）**: 
```python
comm_plan = {
    train_rank: {
        "src_pp_rank": 0,
        "tgt_devices": [infer_rank_0, infer_rank_1, ...],
        "group_name": "model_update_group_0",
        "master_addr": "192.168.1.1",
        "master_port": 29500,
    }
}
```

#### 5.2 NCCL Offload（`roll/utils/offload_nccl.py`）

当启用 `offload_nccl=True` 时，ROLL 会在模型同步完成后释放 NCCL 通信缓冲区，节省 GPU 显存。

### 六、RL 算法库

ROLL 在 `roll/utils/functionals.py` 中实现了丰富的 RL 算法组件。

#### 6.1 PPO（Proximal Policy Optimization）

```python
# 核心公式
ratio = exp(log_probs - old_log_probs)
surr1 = ratio * advantages
surr2 = clamp(ratio, 1 - clip_epsilon, 1 + clip_epsilon) * advantages
policy_loss = -min(surr1, surr2)

# 需要 Critic 网络估计 Value
# 使用 GAE 计算 Advantage
```

**配置**:
```yaml
adv_estimator: gae
ppo_epochs: 4
value_clip: 0.5
```

#### 6.2 GRPO（Group Relative Policy Optimization）

```python
# 对同一 prompt 的 K 个 response 进行组内标准化
advantages = (rewards - mean(rewards)) / (std(rewards) + eps)

# 无需 Critic 网络
# 使用 group 内的相对奖励作为 baseline
```

**配置**:
```yaml
adv_estimator: grpo
num_return_sequences_in_group: 8
```

#### 6.3 Reinforce++

```python
# 使用 running mean 作为 baseline
baseline = running_moments.mean
advantages = rewards - baseline

# 更新 running moments
running_moments.update(rewards)
```

**配置**:
```yaml
adv_estimator: reinforce
```

#### 6.4 TOPR（Token-level Optimal Policy Regularization）

TOPR 对正样本和负样本使用不同的权重：

```python
# 正样本 (reward > 0): 使用 topr_positive_weight
# 负样本 (reward <= 0): 使用 topr_negative_weight
loss = positive_weight * positive_loss + negative_weight * negative_loss
```

**配置**:
```yaml
topr_positive_weight: 1.0
topr_negative_weight: 1.0
```

#### 6.5 RAFT++（Reward-Aware Fine-Tuning）

```python
# 只使用高奖励样本进行训练
# 过滤掉奖励低于阈值的样本
filtered_samples = samples[rewards > threshold]
loss = language_modeling_loss(filtered_samples)
```

#### 6.6 GSPO（Group Supervised Policy Optimization）

```python
# 结合 GRPO 和监督学习
# 使用 group 内的最佳 response 作为正样本
# 使用 group 内的最差 response 作为负样本
```

#### 6.7 GiGPO（Stepwise RL for Agentic）

GiGPO 是 ROLL 为 Agentic RL 设计的 stepwise 算法：

```python
# 每个 step 都有独立的 reward
# 使用 step-level advantage 进行训练
# 支持折扣回报: G_t = r_t + gamma * G_{t+1}
```

**配置**:
```yaml
adv_estimator: gigpo
step_reward_gamma: 0.99
```

#### 6.8 StarPO（Trajectory-wise RL for Agentic）

StarPO 使用整条轨迹的奖励进行训练：

```python

```

LitePPO 使用小型 Critic 网络（mini-critic）来降低 PPO 的计算开销：

### 八、异步并行机制

#### 8.1 Sample-level 异步 Rollout

在 RLVR Pipeline 中，GenerateScheduler 实现了 sample-level 的异步并行：

```
传统同步方式:
  [Prompt 1-64] → 所有 DP Worker → 等待全部完成 → [Response 1-64]

异步方式 (generate_opt_level=1):
  Prompt 1 → DP Worker 0
  Prompt 2 → DP Worker 1 (负载最小)
  Prompt 3 → DP Worker 0 (已完成 Prompt 1)
  ...
  每个 response 完成后立即回调
```

**优势**: 消除了长尾延迟（slow prompt 不会阻塞其他 prompt）。

#### 8.2 Environment-level 异步 Rollout

在 Agentic Pipeline 中，RolloutScheduler 实现了环境级别的异步并行：

```
Environment 0 ──→ Step 1 → Step 2 → Step 3 → Done
Environment 1 ──→ Step 1 → Step 2 → Done
Environment 2 ──→ Step 1 → Step 2 → Step 3 → Step 4 → Done
                  ↑                                    ↑
                  各环境独立推进，互不阻塞
```

**GroupQueue 机制**:
- 每个环境组（group）维护一个 GroupQueue
- GroupQueue 管理多个 episode 的生命周期
- 支持 group_size_redundancy（冗余生成，提高容错性）
- 支持 group_filter（过滤低质量的 rollout 组）

#### 8.3 异步训练

当 `async_generation_ratio > 0` 时，训练和 rollout 可以并行执行：

```
Step N:   [Train on Batch N] ←──── [Rollout for Batch N+1]
Step N+1: [Train on Batch N+1] ←── [Rollout for Batch N+2]
```

**async_generation_ratio** 控制预生成的 episode 数量，值越大预生成越多，但数据的 on-policy 程度越低。

### 九、Sequence Packing 与 Dynamic Batching

#### 9.1 Sequence Packing（`roll/utils/sequence_packing.py`）

将多个短序列打包到一个长序列中，消除 padding 浪费：

```
传统 padding:
  [Token Token Token PAD PAD PAD PAD PAD]  ← 62.5% 浪费
  [Token Token Token Token Token PAD PAD PAD]

Sequence Packing:
  [Token Token Token | Token Token Token Token Token]  ← 0% 浪费
  使用 attention mask 区分不同序列
```

仅在 Megatron 策略中支持（`use_sequence_packing: true`）。

#### 9.2 Dynamic Batching（`roll/utils/dynamic_batching.py`）

根据序列长度动态组装 batch，最小化 padding：
