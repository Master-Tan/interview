## Agentic SFT TunningFactory — 分布式架构与算法

### 一、分布式训练概览

本框架支持三种主流分布式训练方案，覆盖从单机多卡到多机多卡的各种场景：

| 方案 | 配置方式 | 适用场景 | 显存优化级别 |
|------|---------|---------|------------|
| **DeepSpeed ZeRO-2** | `--deepspeed scripts/ds_zero2.json` | 7B~13B 模型全参数训练 | ★★★ |
| **DeepSpeed ZeRO-3** | `--deepspeed scripts/ds_zero3.json` | 13B~72B 大模型训练 | ★★★★★ |
| **PyTorch FSDP** | `--fsdp "full_shard"` | 替代 DeepSpeed 的原生方案 | ★★★★ |
| **序列并行 (SP)** | `--sequence_parallel_size N` | 超长序列训练 | ★★★ (长度维度) |

### 二、DeepSpeed ZeRO 优化

#### 2.1 ZeRO 核心思想

ZeRO (Zero Redundancy Optimizer) 的核心思想是**消除数据并行中的冗余存储**。在标准数据并行中，每个 GPU 都持有完整的模型参数、梯度和优化器状态的副本，造成大量显存浪费。ZeRO 将这些状态分片到不同 GPU 上，需要时再通过通信聚合。

#### 2.2 ZeRO 三个阶段

| 阶段 | 分片内容 | 显存节省 | 通信开销 |
|------|---------|---------|---------|
| **ZeRO-1** | 优化器状态 (OS) | ~4x | 与 DDP 相同 |
| **ZeRO-2** | 优化器状态 + 梯度 (OS+G) | ~8x | 略高于 DDP |
| **ZeRO-3** | 优化器状态 + 梯度 + 参数 (OS+G+P) | ~N 倍 (N=GPU数) | 显著增加 |

**显存占用分析**（以 7B fp16 模型为例）：

一个 7B 参数的模型，使用 Adam 优化器 + fp16 混合精度训练：
- **模型参数**：7B × 2 bytes (fp16) = 14 GB
- **梯度**：7B × 2 bytes = 14 GB
- **优化器状态**：7B × (4 + 4 + 4) bytes (fp32 参数副本 + 一阶矩 + 二阶矩) = 84 GB
- **总计**：~112 GB（单卡放不下）

使用 ZeRO-2（8 卡）：
- 优化器状态分片：84 / 8 = 10.5 GB/卡
- 梯度分片：14 / 8 = 1.75 GB/卡
- 参数不分片：14 GB/卡
- **总计**：~26.25 GB/卡 ✓

使用 ZeRO-3（8 卡）：
- 所有状态分片：112 / 8 = 14 GB/卡
- **总计**：~14 GB/卡 ✓✓

#### 2.3 项目中的 ZeRO-2 配置

```json
// scripts/ds_zero2.json
{
  "train_batch_size": "auto",
  "train_micro_batch_size_per_gpu": "auto",
  "gradient_accumulation_steps": "auto",
  "gradient_clipping": "auto",
  "zero_allow_untested_optimizer": true,
  "fp16": {
    "enabled": "auto",
    "loss_scale": 0,              // 动态 loss scaling
    "loss_scale_window": 1000,
    "initial_scale_power": 16,
    "hysteresis": 2,
    "min_loss_scale": 1
  },
  "bf16": {
    "enabled": "auto"
  },
  "zero_optimization": {
    "stage": 2,
    "allgather_partitions": true,     // AllGather 分区优化
    "allgather_bucket_size": 5e8,     // AllGather 桶大小 (500MB)
    "overlap_comm": true,             // 通信与计算重叠
    "reduce_scatter": true,           // 使用 ReduceScatter 替代 AllReduce
    "reduce_bucket_size": 5e8,        // Reduce 桶大小
    "contiguous_gradients": true,     // 连续梯度内存
    "round_robin_gradients": true     // 轮询梯度分配
  }
}
```

**关键配置解读**：
- **`overlap_comm: true`**：将梯度通信与反向传播计算重叠，隐藏通信延迟
- **`reduce_scatter: true`**：使用 ReduceScatter 替代 AllReduce，减少通信量
- **`allgather_bucket_size / reduce_bucket_size`**：控制通信粒度，过大增加延迟，过小增加通信次数
- **`round_robin_gradients: true`**：将梯度轮询分配到不同 rank，平衡内存使用
- **`contiguous_gradients: true`**：将梯度存储在连续内存中，减少内存碎片

#### 2.4 项目中的 ZeRO-3 配置

```json
// scripts/ds_zero3.json
{
  "zero_optimization": {
    "stage": 3,
    "overlap_comm": true,
    "contiguous_gradients": true,
    "sub_group_size": 1e9,                        // 参数子组大小
    "reduce_bucket_size": "auto",
    "stage3_prefetch_bucket_size": "auto",         // 预取桶大小
    "stage3_param_persistence_threshold": "auto",  // 小参数持久化阈值
    "stage3_max_live_parameters": 1e9,             // 最大活跃参数数
    "stage3_max_reuse_distance": 1e9,              // 最大参数重用距离
    "stage3_gather_16bit_weights_on_model_save": true  // 保存时聚合 fp16 权重
  }
}
```

**ZeRO-3 特有配置解读**：
- **`stage3_prefetch_bucket_size`**：预取下一层参数的桶大小，实现计算与通信重叠
- **`stage3_param_persistence_threshold`**：小于此阈值的参数不分片，保持在每个 GPU 上（如 LayerNorm 参数）
- **`stage3_max_live_parameters`**：同时保持在 GPU 上的最大参数数量，控制显存峰值
- **`stage3_gather_16bit_weights_on_model_save`**：保存 checkpoint 时将分片参数聚合为完整的 fp16 权重

#### 2.5 ZeRO-3 与 LoRA 的兼容性

框架在 `adapter.py` 中对 ZeRO-3 + LoRA 做了特殊处理：

```python
if is_deepspeed_zero3_enabled():
    assert len(model_args.adapter_name_or_path) == 1, \
        "Cannot use multiple adapters in DeepSpeed ZeRO-3."
```

ZeRO-3 下 LoRA 的限制：
- 只能使用单个 adapter（不支持多 adapter 合并后训练）
- 加载 adapter 时需要使用 `GatheredParameters` 上下文管理器
- Value Head 的加载也需要在 `GatheredParameters` 中进行

#### 2.6 ZeRO-3 CPU Offload

框架还提供了 ZeRO-3 + CPU Offload 配置（`ds_zero3_cpuoffload.json`），将优化器状态和部分参数卸载到 CPU 内存，进一步降低 GPU 显存需求，但会增加训练时间。

### 三、PyTorch FSDP

#### 3.1 FSDP 核心思想

FSDP (Fully Sharded Data Parallel) 是 PyTorch 原生的分布式训练方案，功能类似 DeepSpeed ZeRO-3，将模型参数、梯度和优化器状态完全分片。

#### 3.2 项目中的 FSDP 配置

```json
// scripts/fsdp_config.json
{
  "fsdp_auto_wrap_policy": "TRANSFORMER_BASED_WRAP",  // 按 Transformer 层自动包装
  "fsdp_backward_prefetch": "BACKWARD_PRE",           // 反向传播预取策略
  "fsdp_forward_prefetch": false,
  "fsdp_cpu_ram_efficient_loading": true,              // CPU 内存高效加载
  "fsdp_offload_params": false,                        // 不卸载参数到 CPU
  "fsdp_sharding_strategy": "FULL_SHARD",              // 完全分片（等价 ZeRO-3）
  "fsdp_state_dict_type": "FULL_STATE_DICT",           // 保存完整状态字典
  "fsdp_sync_module_states": true,                     // 同步模块状态
  "fsdp_use_orig_params": true                         // 使用原始参数（兼容 PEFT）
}
```

**关键配置解读**：
- **`TRANSFORMER_BASED_WRAP`**：自动识别 Transformer 层并包装为 FSDP 单元，每个层独立分片
- **`BACKWARD_PRE`**：在反向传播开始前预取下一层参数，实现通信与计算重叠
- **`FULL_SHARD`**：完全分片策略，等价于 ZeRO-3
- **`fsdp_use_orig_params: true`**：必须为 true 才能兼容 PEFT/LoRA

#### 3.3 FSDP vs DeepSpeed 选择建议

| 维度 | DeepSpeed | FSDP |
|------|-----------|------|
| 生态成熟度 | ★★★★★ | ★★★★ |
| PyTorch 原生 | ✗ | ✓ |
| CPU Offload | ✓ | ✓ |
| 混合精度 | 自带实现 | 依赖 PyTorch AMP |
| LoRA 兼容性 | 需要特殊处理 | 需要 `use_orig_params` |
| 多节点通信 | NCCL + 自定义 | NCCL |
| 配置复杂度 | 较高 | 较低 |

**框架中的处理**：在 `patcher.py` 的 `patch_config()` 中，会根据是否启用 FSDP 来调整模型加载行为：

```python
# deepspeed zero3 和 fsdp 下保持 float32 加载
if (not is_deepspeed_zero3_enabled() and not is_fsdp_enabled()) or model_args.quantization_bit is not None:
    init_kwargs["torch_dtype"] = model_args.compute_dtype
```

### 四、序列并行 (Sequence Parallelism)

#### 4.1 为什么需要序列并行

数据并行和模型并行解决的是**模型规模**的扩展问题，但当**序列长度**非常长时（如 32K、128K），单个 GPU 的显存仍然不够，因为注意力机制的显存占用与序列长度的平方成正比：

```
Attention 显存 ∝ O(batch_size × num_heads × seq_len²)
```

序列并行将一个长序列切分到多个 GPU 上，每个 GPU 只处理序列的一部分。

#### 4.2 框架支持的序列并行模式

通过 `--sequence_parallel_size N` 和 `--sequence_parallel_mode` 参数启用：

| 模式 | 参数值 | 原理 | 通信模式 |
|------|--------|------|---------|
| **Ulysses** | `ulysses` | 均匀切分序列，AllToAll 通信 | AllToAll |
| **Zigzag-Ring** | `zigzag-ring` | 交错切分序列，Ring 通信 | Ring AllReduce |

#### 4.3 Ulysses 序列并行

**原理**：将序列均匀切分为 N 段，每个 GPU 处理一段。在注意力计算前通过 AllToAll 通信交换 Q/K/V，使每个 GPU 拥有完整序列的部分注意力头。

```
GPU 0: tokens [0, L/N)      → AllToAll → heads [0, H/N) 的完整序列
GPU 1: tokens [L/N, 2L/N)   → AllToAll → heads [H/N, 2H/N) 的完整序列
...
GPU N-1: tokens [(N-1)L/N, L) → AllToAll → heads [(N-1)H/N, H) 的完整序列
```

**在 Collator 中的实现** (`collator.py`)：

```python
class SFTDataCollatorWithSequenceParallel:
    def process_sp_dataset(self, seq_ids):
        if self.sequence_parallel_mode == "ulysses":
            # 均匀切分
            split_size = seq_ids.shape[1] // self.sequence_parallel_size
            chunks = torch.split(seq_ids, split_size, dim=1)
            return chunks[self.rank]
```

#### 4.4 Zigzag-Ring 序列并行

**原理**：将序列交错切分，每个 GPU 获得序列的前半部分和后半部分的对称片段。通过 Ring 通信模式传递 K/V，实现因果注意力的分布式计算。

```
GPU 0: tokens [0, L/2N) + tokens [L - L/2N, L)
GPU 1: tokens [L/2N, 2L/2N) + tokens [L - 2L/2N, L - L/2N)
...
```

**在 Collator 中的实现**：

```python
def process_sp_dataset(self, seq_ids):
    if self.sequence_parallel_mode == "zigzag-ring":
        split_size = seq_ids.shape[1] // (2 * self.sequence_parallel_size)
        chunks = torch.split(seq_ids, split_size, dim=1)
        # 取前半和后半的对称片段
        return torch.cat(
            (chunks[self.rank], chunks[2 * self.sequence_parallel_size - self.rank - 1]),
            dim=1
        )
```

#### 4.5 序列并行的配置约束

框架在多处对序列并行进行了约束检查：

1. **注意力 Dropout 必须为 0**（`patcher.py`）：
```python
if model_args.sequence_parallel_size > 1 and config.attention_dropout != 0.0:
    config.attention_dropout = 0.0  # SP 不支持 attention dropout
```

2. **Packing 对齐**（`data_args.py`）：
```python
# 启用 SP + Packing 时，序列长度需要对齐到 2*SP 的倍数
sequence_length_pad_multiple: int  # 应设为 2 * sequence_parallel_size 的倍数
```

3. **DataLoader 适配**（`trainer.py`）：
```python
# SP 下 DataLoader 的进程数需要除以 SP size
prepare_data_loader(
    num_processes=world_size // sequence_parallel_size,
    process_index=process_index // sequence_parallel_size,
)
```

4. **Dummy Forward**（`trainer.py`）：
```python
# 首次训练步骤前需要做一次 dummy forward 初始化通信组
if not self._has_dummy_forwarded and model.sequence_parallel_group is not None:
    model.eval()
    with torch.no_grad():
        _ = model(**inputs)
    model.train()
    self._has_dummy_forwarded = True
```

### 五、混合精度训练

#### 5.1 支持的精度模式

| 模式 | 参数 | 说明 |
|------|------|------|
| FP16 | `--fp16` | 半精度浮点，需要 loss scaling |
| BF16 | `--bf16` | Brain Float16，动态范围更大，推荐 A100/H100 |
| Pure BF16 | `--pure_bf16` | 纯 BF16 训练，不使用混合精度 |

#### 5.2 FP16 Loss Scaling

FP16 训练中，小梯度可能下溢为 0。DeepSpeed 配置中的 loss scaling 机制：

```json
"fp16": {
    "loss_scale": 0,              // 0 表示动态 loss scaling
    "loss_scale_window": 1000,    // 每 1000 步尝试增大 scale
    "initial_scale_power": 16,    // 初始 scale = 2^16 = 65536
    "hysteresis": 2,              // 连续 2 次溢出才减小 scale
    "min_loss_scale": 1           // 最小 scale 值
}
```

#### 5.3 精度转换策略

框架在 `patcher.py` 中根据不同场景选择精度：

```python
# 推断最优精度：bf16 > fp16 > fp32
model_args.compute_dtype = infer_optim_dtype(model_dtype=config.torch_dtype)

# DeepSpeed ZeRO-3 和 FSDP 下保持 float32 加载（框架内部处理精度转换）
if not is_deepspeed_zero3_enabled() and not is_fsdp_enabled():
    init_kwargs["torch_dtype"] = model_args.compute_dtype
```

### 六、注意力加速

#### 6.1 FlashAttention-2

通过 `--flash_attn fa2` 启用，利用 IO-aware 的 tiling 算法减少 HBM 访问：

- **显存**：从 O(N²) 降低到 O(N)
- **速度**：2-4x 加速
- **要求**：Ampere 及以上架构 (A100/H100/RTX 4090)

#### 6.2 SDPA (Scaled Dot-Product Attention)

PyTorch 2.0+ 内置的注意力实现，自动选择最优后端：

```python
--flash_attn sdpa  # 自动选择 FlashAttention / Memory-Efficient / Math 后端
```

#### 6.3 Liger Kernel

通过 `--enable_liger_kernel` 启用，使用 Triton 编写的融合算子加速：

- 融合 RMSNorm + 残差连接
- 融合 SwiGLU 激活
- 融合 Cross-Entropy Loss
- 减少 kernel launch 开销和中间张量显存

### 七、梯度优化技术

#### 7.1 梯度检查点 (Gradient Checkpointing)

默认启用（除非 `--disable_gradient_checkpointing`），用时间换空间：

- **原理**：前向传播时不保存中间激活值，反向传播时重新计算
- **效果**：显存降低约 60%，训练时间增加约 30%
- **实现**：在 `model_utils/checkpointing.py` 中的 `prepare_model_for_training()` 配置

#### 7.2 梯度累积 (Gradient Accumulation)

通过 `--gradient_accumulation_steps N` 模拟更大的 batch size：

```
有效 batch size = per_device_batch_size × num_gpus × gradient_accumulation_steps
```

#### 7.3 梯度裁剪 (Gradient Clipping)

DeepSpeed 配置中的 `gradient_clipping: "auto"` 会自动使用 HuggingFace TrainingArguments 中的 `max_grad_norm`（默认 1.0）。

### 八、通信优化

#### 8.1 通信与计算重叠

DeepSpeed 的 `overlap_comm: true` 实现了：
- **ZeRO-2**：梯度 ReduceScatter 与反向传播重叠
- **ZeRO-3**：参数 AllGather 与前向传播重叠，梯度 ReduceScatter 与反向传播重叠

#### 8.2 桶化通信 (Bucketing)

将小张量的通信合并为大桶，减少通信次数：

```json
"allgather_bucket_size": 5e8,  // 500MB 的 AllGather 桶
"reduce_bucket_size": 5e8      // 500MB 的 Reduce 桶
```

**调优建议**：
- 桶太大：增加通信延迟，减少重叠机会
- 桶太小：增加通信次数，增加 kernel launch 开销
- 一般 200MB~500MB 是较好的平衡点

#### 8.3 多节点训练

框架通过 `scripts/cluster.json` 和 `cluster_multigpu.json` 配置多节点训练：

```bash
# 通过 MDL 平台提交多节点任务
nebulactl run mdl \
    --worker_count=8 \           # 8 个 worker
    --file.cluster_file=scripts/cluster.json \
    --user_params="..."
```

### 十、分布式训练最佳实践

#### 10.1 方案选择决策树

```
模型大小？
├─ ≤ 7B
│   ├─ LoRA → 单卡即可，无需分布式
│   └─ Full → ZeRO-2 (4~8 卡)
├─ 7B ~ 13B
│   ├─ LoRA → 单卡 / 多卡 DDP
│   └─ Full → ZeRO-2 (8 卡) 或 ZeRO-3 (4~8 卡)
├─ 13B ~ 70B
│   ├─ LoRA → ZeRO-2 (4~8 卡)
│   └─ Full → ZeRO-3 (16~64 卡)
└─ > 70B
    └─ ZeRO-3 + CPU Offload (32~128 卡)

序列长度？
├─ ≤ 4K → 标准训练
├─ 4K ~ 32K → FlashAttention-2 + 梯度检查点
└─ > 32K → 序列并行 (Ulysses/Zigzag-Ring)
```

#### 10.2 常见问题排查

| 问题 | 可能原因 | 解决方案 |
|------|---------|---------|
| OOM | batch size 过大 | 减小 batch size，增大 gradient_accumulation |
| OOM | 序列过长 | 减小 cutoff_len，启用梯度检查点 |
| OOM | ZeRO-2 不够 | 切换到 ZeRO-3 |
| 训练速度慢 | 通信瓶颈 | 检查网络带宽，调整 bucket size |
| Loss NaN | FP16 溢出 | 切换到 BF16，或调整 loss scaling |
| 多卡不一致 | 随机种子 | 设置 `--seed` 和 `--full_determinism` |
