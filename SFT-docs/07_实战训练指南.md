## Agentic SFT TunningFactory — 实战训练指南

> 本文档记录我们在 Agentic SFT 项目中**实际使用的训练流程、参数配置、踩过的坑和解决方案**，面向团队成员快速上手和问题排查。

### 一、训练环境与基础设施

#### 1.1 硬件资源

| 项目 | 配置 |
|------|------|
| **训练集群** | 星云 MDL 平台 |
| **训练队列** | `amap_common_h20_na175`（H20 GPU） |
| **典型机器数** | 4 卡（LoRA）/ 8 卡（Full）/ 16 卡（Megatron） |
| **算法镜像** | `pytorch260`（推荐）/ `pytorch220`（旧版 QLoRA） |

#### 1.2 存储配置

训练数据和 checkpoint 通过 OSS 挂载到集群本地路径：

```
OSS Bucket:  amap-info-alignment
OSS Endpoint: oss-cn-zhangjiakou.aliyuncs.com
本地挂载路径: /data/oss_bucket_0/
```

**路径映射规则**：OSS 上 `oss://amap-info-alignment/dir1/file` 对应集群内 `/data/oss_bucket_0/dir1/file`。

在 `scripts/config.sh` 中填写 OSS 凭证和队列名：

```bash

OSS_ENDPOINT="oss-cn-zhangjiakou.aliyuncs.com"
```

> ⚠️ **注意**：`config.json` 是带有实际凭证的配置文件，请勿提交到公开仓库。

| **OSS 混合** | `oss://amap-info-alignment/yihao/sync/data/agent-rl/intent/sft/toucan_oss_final_25k.jsonl` | 25,000 | 经过筛选混合的最终数据 |

| **Megatron 训练用** | `oss://amap-info-alignment/yihao/sync/data/agent-rl/intent/sft/x0824-1020-80k_..._sft.jsonl` | ~80,000 | Qwen3-30B-A3B 全量训练数据 |

#### 2.2 数据格式

框架支持两种主要格式：

**Alpaca 格式**（通过 `--prompt`/`--query`/`--response` 指定列名）：

```json
{"instruction": "请翻译以下句子", "input": "Hello world", "output": "你好世界"}
```

**ShareGPT 格式**（通过 `--dataset` 指定已注册数据集，或 `--messages` 指定列名）：

```json
{
  "messages": [
    {"role": "system", "content": "You are a helpful assistant."},
    {"role": "user", "content": "你好"},
    {"role": "assistant", "content": "你好！有什么可以帮你的？"}
  ]
}
```

#### 2.3 数据预处理

对于 ShareGPT 格式的数据，如果需要将 `system` 消息从 `messages` 列表中提取到顶层字段，可使用 `data/trans2sharegpt.py`：

```bash
python data/trans2sharegpt.py
```

该脚本会：
1. 从 `messages` 中提取 `role=system` 的 `content` 到顶层 `system` 字段
2. 从 `messages` 列表中移除 `system` 消息
3. 输出处理后的 JSONL 文件

> 使用前需修改脚本底部的 `input_file_path` 和 `output_file_path`。

### 三、实际训练配置

#### 3.1 SFT Full 微调（DeepSpeed）

**适用场景**：7B 及以下模型的全参数微调。

**启动脚本**：`scripts/sft_ds.sh`

**我们实际使用的核心参数**：

| 参数 | 值 | 说明 |
|------|-----|------|
| `--finetuning_type` | `full` | 全参数微调 |
| `--per_device_train_batch_size` | `2` | 每卡 batch size |
| `--gradient_accumulation_steps` | `4` | 梯度累积步数 |
| `--learning_rate` | `2e-5` | 学习率 |
| `--lr_scheduler_type` | `cosine` | 余弦退火 |
| `--cutoff_len` | `1024` | 最大序列长度 |
| `--save_steps` | `50` | 每 50 步保存 checkpoint |
| `--max_steps` | `100` | 最大训练步数 |
| `--deepspeed` | `scripts/ds_zero2.json` | DeepSpeed ZeRO-2 |
| `--bf16` | — | BF16 混合精度 |
| `--preprocessing_num_workers` | `8` | 数据预处理并行数 |
| `--dataloader_num_workers` | `4` | DataLoader 并行数 |
| `WORLD_SIZE` | `4` | 4 卡训练 |

**有效 batch size** = `per_device_train_batch_size` × `gradient_accumulation_steps` × `WORLD_SIZE` = 2 × 4 × 4 = **32**

#### 3.2 SFT LoRA 微调

**适用场景**：显存受限或快速实验迭代。

**启动脚本**：`scripts/sft_lora.sh`

**与 Full 微调的关键差异**：

| 参数 | 值 | 说明 |
|------|-----|------|
| `--finetuning_type` | `lora` | LoRA 微调 |
| `--lora_target` | `W_pack,o_proj,gate_proj,up_proj,down_proj` | LoRA 目标模块 |
| `--per_device_train_batch_size` | `4` | 每卡 batch size（LoRA 显存占用更小） |
| `--learning_rate` | `5e-5` | 学习率（LoRA 通常更高） |
| `--save_steps` | `100` | 保存间隔 |
| `--max_steps` | `200` | 训练步数 |

> 💡 **基于已有 LoRA checkpoint 继续训练**：设置 `LORA_CKPT` 变量并在 args 中添加 `--adapter_name_or_path`。

#### 3.3 SFT QLoRA 微调

**适用场景**：单卡训练大模型（如 14B+ 模型在单张 GPU 上训练）。

**启动脚本**：`scripts/sft_qlora.sh`

**关键差异**：

| 参数 | 值 | 说明 |
|------|-----|------|
| `--quantization_bit` | `4` | 4-bit 量化 |
| `--lora_target` | `c_attn,attn.c_proj,w1,w2,mlp.c_proj` | 目标模块（不同模型不同） |
| `WORLD_SIZE` | `1` | 单卡训练 |
| `algo_name` | `pytorch220` | QLoRA 需要旧版镜像 |

> ⚠️ **注意**：QLoRA 使用 `pytorch220` 镜像，而非 `pytorch260`。

#### 3.4 Megatron 加速训练（大模型推荐）

**适用场景**：Qwen3-4B、Qwen3-30B-A3B 等模型的高效全量训练。

**启动方式**：通过 `scripts/sft_mdl_launch.sh` → `launcher.py` → `scripts/sft_run_megatron.sh` 三级调用。

**我们在 Qwen3-30B-A3B 上实际使用的参数**：

| 参数 | 值 | 说明 |
|------|-----|------|
| `--model_name_or_path` | `Qwen/Qwen3-30B-A3B` | 基座模型 |
| `--template` | `qwen3` | Prompt 模板 |
| `--finetuning_type` | `full` | 全参数微调 |
| `--use_turbo` | — | 启用 Megatron Turbo 加速 |
| `--tensor_model_parallel_size` | `2` | 张量并行度 |
| `--pipeline_model_parallel_size` | `1` | 流水线并行度 |
| `--context_parallel_size` | `8` | 上下文并行度 |
| `--sequence_parallel` | — | 启用序列并行 |
| `--per_device_train_batch_size` | `1` | 每卡 batch size |
| `--gradient_accumulation_steps` | `8` | 梯度累积 |
| `--learning_rate` | `1e-5` | 学习率 |
| `--cutoff_len` | `65536` | 最大序列长度（64K） |
| `--num_train_epochs` | `1.0` | 训练 1 个 epoch |
| `--enable_thinking` | `True` | 启用推理思考模式 |
| `--report_to` | `swanlab` | 使用 SwanLab 监控 |
| `WORLD_SIZE` | `16` | 16 卡训练 |

**并行策略说明**：
- **TP=2**：每 2 张卡做张量并行，切分模型权重
- **CP=8**：8 路上下文并行，支持 64K 超长序列
- **SP**：序列并行，与 TP 配合减少激活值显存

### 四、DeepSpeed 配置详解

#### 4.1 ZeRO-2（推荐用于 ≤7B 模型）

配置文件：`scripts/ds_zero2.json`

```json
{
  "zero_optimization": {
    "stage": 2,
    "allgather_partitions": true,
    "allgather_bucket_size": 5e8,
    "overlap_comm": true,
    "reduce_scatter": true,
    "reduce_bucket_size": 5e8,
    "contiguous_gradients": true,
    "round_robin_gradients": true
  }
}
```

- 切分优化器状态和梯度，不切分模型参数
- 通信开销较小，训练速度快
- 适合 7B 及以下模型

#### 4.2 ZeRO-3（推荐用于 13B-14B 模型）

配置文件：`scripts/ds_zero3.json`

- 切分优化器状态、梯度和模型参数
- 显存占用更低，但通信开销更大
- `stage3_gather_16bit_weights_on_model_save: true` 确保保存完整权重

#### 4.3 ZeRO-3 + CPU Offload（显存极度紧张时）

配置文件：`scripts/ds_zero3_cpuoffload.json`

- 在 ZeRO-3 基础上将优化器状态和参数卸载到 CPU
- 显存占用最低，但训练速度显著下降
- 仅在显存实在不够时使用

**选择建议**：

| 模型规模 | 推荐配置 |
|---------|---------|
| ≤ 7B | ZeRO-2 |
| 13B-14B | ZeRO-3 |
| > 14B（DeepSpeed） | ZeRO-3 + CPU Offload |
| > 14B（推荐） | Megatron Turbo（`--use_turbo`） |

### 六、训练后操作

#### 6.1 LoRA 权重合并

训练完成后，需要将 LoRA adapter 合并回基座模型才能用于推理部署：

```bash
# 在 scripts/merge_lora.sh 中配置
MODEL_NAME="<base_model_path>"        # 基座模型路径
LORA_CKPT="<lora_checkpoint_path>"    # LoRA checkpoint 路径
EXPORD_DIR="local/tmp/ckpt_save_path/"  # 合并后模型保存路径

# 关键参数
--export_size=4   # 单个权重文件最大 4GB
```

#### 6.2 Megatron Checkpoint 转换

Megatron Turbo 训练产出的 checkpoint 需要转换为 HuggingFace 格式：

```bash
bash scripts/convert_turbo_to_hf.sh
```

#### 6.3 模型推理验证

使用 `scripts/inference.sh` 进行批量推理验证：

```bash
# 关键配置
MODEL_NAME="<model_path>"
INPUT="data/test_input.json"
OUTPUT="/data/oss_bucket_0/xxx/output.json"
GENERATE_MODE="default"   # 或 vllm / vllm-async / vllm-multi-node

# 生成参数
--temperature=1.0
--top_p=0.8
--top_k=100
--max_new_tokens=512
```

### 七、常见问题与排查

#### 7.1 OOM（显存不足）

**现象**：`CUDA out of memory` 或训练启动后立即崩溃。

**排查与解决**：

| 方案 | 操作 | 效果 |
|------|------|------|
| **降低 batch size** | 减小 `--per_device_train_batch_size`，增大 `--gradient_accumulation_steps` 保持有效 batch size 不变 | ⭐⭐⭐ |
| **缩短序列长度** | 减小 `--cutoff_len` | ⭐⭐⭐ |
| **启用梯度检查点** | 默认已启用，确认没有设置 `--disable_gradient_checkpointing` | ⭐⭐ |
| **切换 ZeRO 策略** | ZeRO-2 → ZeRO-3 → ZeRO-3 + CPU Offload | ⭐⭐ |
| **使用 LoRA/QLoRA** | 从 `full` 切换为 `lora` 或加上 `--quantization_bit 4` | ⭐⭐⭐ |
| **使用 Megatron Turbo** | 添加 `--use_turbo` 并配置张量/流水线并行 | ⭐⭐⭐ |
| **增加机器数** | 增大 `WORLD_SIZE` | ⭐ |

#### 7.2 Loss 不下降或 NaN

**现象**：训练 loss 长时间不变、突然飙升或出现 NaN。

**排查与解决**：

- **学习率过大**：Full 微调建议 `1e-5` ~ `2e-5`，LoRA 建议 `5e-5` ~ `1e-4`
- **数据质量问题**：检查数据中是否有空样本、超长样本或格式错误
- **BF16 溢出**：确认使用 `--bf16` 而非 `--fp16`，BF16 的动态范围更大
- **梯度裁剪**：DeepSpeed 配置中 `gradient_clipping` 设为 `auto`，框架会自动处理
- **检查 template**：确保 `--template` 与模型匹配（如 Qwen3 用 `qwen3`），错误的 template 会导致 loss 异常

#### 7.3 数据加载失败

**现象**：`FileNotFoundError` 或数据预处理卡住。

**排查与解决**：

- **OSS 路径问题**：确认 OSS 文件路径正确，且在集群内对应 `/data/oss_bucket_0/` 下的路径
- **JSON 格式错误**：使用 `python -m json.tool < data.json` 验证 JSON 格式
- **JSONL 编码问题**：确保文件为 UTF-8 编码
- **列名不匹配**：检查 `--prompt`/`--query`/`--response` 是否与数据文件中的字段名一致
- **预处理并行冲突**：如果预处理卡住，尝试减小 `--preprocessing_num_workers`

#### 7.4 Checkpoint 保存/加载问题

**现象**：checkpoint 保存失败、加载后 loss 异常。

**排查与解决**：

- **磁盘空间不足**：Full 微调的 checkpoint 很大（7B 模型约 14GB/个），确保 OSS 空间充足
- **ZeRO-3 保存**：确认 `stage3_gather_16bit_weights_on_model_save: true`，否则保存的权重不完整
- **LoRA checkpoint 路径**：格式为 `your_nebula_project.your_lora_ckpt/version=your_version/ckpt_id=checkpoint-xxx`
- **Megatron checkpoint**：Turbo 模式产出的 checkpoint 必须先通过 `convert_turbo_to_hf.sh` 转换才能用于推理

#### 7.5 多卡训练通信问题

**现象**：训练卡在初始化阶段、NCCL 超时。

**排查与解决**：

- **NCCL 超时**：检查集群网络状态，确认所有节点可互通
- **端口冲突**：如果同一机器上有多个训练任务，可能出现端口冲突
- **集群配置**：确认 `scripts/cluster.json` 配置正确
- **重试**：MDL 平台偶尔有节点故障，重新提交任务即可

#### 7.6 Template 选择错误

**现象**：模型输出乱码、重复生成、loss 异常偏高。

**排查与解决**：

- 每个模型有对应的 prompt template，**必须匹配使用**
- 常用模板：`qwen3`（Qwen3 系列）、`llama2`、`chatglm3` 等
- 所有可用 template 见 `src/llmtuner/extras/template.py`
- 如果不确定，查阅模型的官方文档或参考[常规模型配置](https://aliyuque.antfin.com/uxctvg/yd0939/qzayp5pyyxd0e46h)

#### 7.7 LoRA 目标模块选择

**不同模型的 LoRA 目标模块不同**：

| 模型 | 推荐 `--lora_target` |
|------|---------------------|
| Qwen 系列 | `W_pack,o_proj,gate_proj,up_proj,down_proj` |
| ChatGLM 系列 | `c_attn,attn.c_proj,w1,w2,mlp.c_proj` |
| 通用（自动） | `all`（框架自动识别所有线性层） |

> 💡 如果不确定，使用 `--lora_target all` 让框架自动选择所有线性层。

### 九、快速上手 Checklist

以下是从零开始一次 SFT 训练的完整步骤：

- [ ] **配置环境**：填写 `scripts/config.sh` 中的 OSS 凭证和队列名
- [ ] **准备数据**：将数据上传到 OSS，确认格式为 Alpaca 或 ShareGPT
- [ ] **选择脚本**：根据模型规模和需求选择训练脚本
  - ≤ 7B Full 微调 → `sft_ds.sh`
  - 任意规模 LoRA → `sft_lora.sh`
  - 单卡大模型 → `sft_qlora.sh`
  - 大模型高效训练 → `sft_mdl_launch.sh` + `sft_run_megatron.sh`
- [ ] **配置参数**：在脚本中设置 `MODEL_NAME`、`PROMPT_TEMPLATE`、`INPUT`、`SAVE_MODEL`
- [ ] **提交训练**：执行 `bash scripts/sft_ds.sh`（或对应脚本）
- [ ] **监控训练**：在星云平台或 SwanLab 查看 loss 曲线
- [ ] **保存模型**：LoRA 需要执行 `merge_lora.sh`，Megatron 需要执行 `convert_turbo_to_hf.sh`
- [ ] **验证推理**：使用 `inference.sh` 进行批量推理验证

### 十、参数速查表

#### 10.1 学习率推荐

| 微调方式 | 模型规模 | 推荐学习率 |
|---------|---------|-----------|
| Full SFT | ≤ 7B | `2e-5` |
| Full SFT | 13B-30B | `1e-5` |
| LoRA | 任意 | `5e-5` |
| QLoRA | 任意 | `5e-5` |
| DPO | 任意 | `1e-5` |
| PPO | 任意 | `1e-5` |
| 蒸馏 | 任意 | `2e-5` |

#### 10.2 Batch Size 推荐

| 微调方式 | `per_device_train_batch_size` | `gradient_accumulation_steps` |
|---------|------------------------------|-------------------------------|
| Full SFT | 1-2 | 4-8 |
| LoRA | 4 | 4 |
| QLoRA | 4 | 4 |
| DPO | 1 | 4 |
| PPO | 1 | 4 |
| Megatron | 1 | 8 |

#### 10.3 序列长度推荐
