## Agentic SFT TunningFactory — 框架概述与架构

> 本文档聚焦于我们在 LLaMA-Factory (v0.5.3) 基础上**实际二次开发**的内容，不赘述原版已有功能。

---

### 一、项目定位与二次开发目标

本项目基于开源 LLaMA-Factory (v0.5.3) 进行二次开发，核心目标是将其从一个通用的开源微调工具，改造为**深度集成阿里内部基础设施**、**扩展高级训练能力**的内部生产级框架。

**我们做了什么**：
- 新增**知识蒸馏训练**（`train/distill/`）：完整的 Teacher-Student 蒸馏 pipeline
- 新增**IFT Loss**（Implicit Future Training）：解决 SFT 的 exposure bias 问题
- 新增**序列并行**（Ulysses + Zigzag-Ring）：支持超长序列训练
- 新增**Turbo 加速模式**：集成 `transformers_turbo`，支持 HF↔Turbo 双向转换
- 集成**阿里内部平台**：星云 MDL 提交、MOS 模型仓库、ODPS/AiLake 数据源、OpenLM Hub、ML Tracker
- 新增多个**自定义 Callback**：MOS 上传、交互式 Checkpoint、动态数据集交错、训练中预测
- 新增**LoRA 合并工具**（`train/merge.py`）：独立的 merge 脚本 + 自动 MOS 上传

### 三、二次开发模块详解

#### 3.1 知识蒸馏模块 (`train/distill/`)

**完全新增**的训练阶段，实现了完整的 Teacher-Student 知识蒸馏 pipeline。

**核心文件**：
- `train/distill/trainer.py` — `DistillationTrainer`：继承 `Seq2SeqTrainer`，实现双模型前向传播和混合损失计算
- `train/distill/workflow.py` — 蒸馏训练 workflow：加载 Student + Teacher 双模型
- `train/distill/various_divergence.py` — `VariousDivergence`：多种 KD 目标函数实现
- `data/collator.py` — `DistillDataCollatorWith4DAttentionMask`：为 Student 和 Teacher 分别准备输入

**关键设计**：
- **双模型加载**：Student 模型正常训练，Teacher 模型冻结（通过 DeepSpeed ZeRO-3 或 `accelerator.prepare_model(evaluation_mode=True)` 处理）
- **双 Template**：Student 和 Teacher 可使用不同的 prompt template（`--template` vs `--teacher_template`）
- **多种 KD 目标**：`forward_kl`、`reverse_kl`、`adaptive_kl`、`js_divergence`
- **混合损失**：`L = (1-α) × CE_loss + α × KD_loss`，α 由 `--distill_loss_weight` 控制

#### 3.2 IFT Loss (`train/sft/trainer.py`)

在 `CustomSeq2SeqTrainer` 中新增 `compute_ift_loss()` 方法，实现 Implicit Future Training。

**核心思想**：让模型在"被自己的错误预测污染"的上下文中仍能生成正确 token，缓解 exposure bias。

**实现流程**：
1. 用当前模型做一次前向传播，得到贪心预测 `greedy_preds`
2. 将 ground truth embedding 和贪心预测 embedding 按 λ 比例混合：`(1-λ) × gt + λ × pred`
3. 用混合后的 embedding 再做一次前向传播
4. 使用 `get_cumsum_weight()` 计算累积权重（基于 `torch_discounted_cumsum`），让后面的 token 获得更大的权重

**关键函数**：
- `compute_ift_loss()` — IFT 损失计算
- `get_cumsum_weight()` — 支持多种传播方式（`loss`/`mask`/`logps`）和归一化方式（`L1`/`L2`/`softmax`/`log`）

#### 3.3 序列并行 (`model/model_utils/sequence_parallel.py`)

**完全新增**，支持两种序列并行模式，解决超长序列训练的显存瓶颈。

**核心实现**：
- `init_sp_group()` — 初始化序列并行通信组
- `apply_sequence_parallel()` — 通过 Monkey-patch `transformers` 的 `ALL_ATTENTION_FUNCTIONS["flash_attention_2"]`，将标准 FlashAttention 替换为序列并行版本
- `_flash_attn_forward()` — 统一入口，根据 mode 分发到 `zigzag_ring_flash_attn_func`（来自 `ring_flash_attn` 库）或 `UlyssesAttention`

**配套修改**：
- `train/sft/trainer.py` — 自定义 `get_train_dataloader()` 和 `_get_train_sampler()`，适配 SP 的 DataLoader 分片
- `train/sft/trainer.py` — `training_step()` 中增加 dummy forward 初始化通信组
- `train/sft/trainer.py` — `compute_loss()` 中增加 SP 模式下不 shift labels 的逻辑
- `data/collator.py` — `SFTDataCollatorWithSequenceParallel`：按 SP 模式切分序列

#### 3.4 Turbo 加速模式

集成 `transformers_turbo` 库，提供加速训练能力。

**核心文件**：
- `src/convert_turbo.py` — HF↔Turbo 模型格式双向转换工具
- `train/pt/workflow_turbo.py` — PT 阶段 Turbo workflow
- `train/sft/workflow_turbo.py` — SFT 阶段 Turbo workflow
- `train/dpo/workflow_turbo.py` — DPO 阶段 Turbo workflow

**使用方式**：通过 `--use_turbo` 参数启用，`tuner.py` 中根据此参数分发到对应的 `workflow_turbo.py`。

#### 3.5 MOS 模型仓库集成 (`train/mixin.py`)

**`OpenlmHubUtils` 类**：封装了与 MOS 模型仓库的交互逻辑。

```python
class OpenlmHubUtils:
    def __init__(self):
        self.mos_uri = get_mos_version_uri_in_mdl_task()  # 从 MDL 环境变量获取 MOS URI

    def save_local_model_to_mos(self, ckpt_id, local_state_path, metrics=None):
        push_to_mos(local_state_path, checkpoint_id=ckpt_id, mos_version_uri=self.mos_uri, metrics=metrics)
        shutil.rmtree(local_state_path)  # 上传后删除本地文件
```

**`PushToMosCallback`**：在每次 `on_save` 时自动上传 checkpoint 到 MOS，并附带 TFLOPs 指标。内置了完整的 FLOPs 计算逻辑（参考 Megatron-LLaMA），计算公式考虑了 Attention、FFN、Logits 的前向和反向传播。

#### 3.6 自定义 Callbacks (`extras/callbacks.py`)

| Callback | 触发时机 | 功能 |
|----------|---------|------|
| `PushToMosCallback` | `on_save` | 上传 checkpoint 到 MOS + TFLOPs 计算 |
| `InteractiveCkptCallback` | `on_step_end` | 通过外部信号动态触发 checkpoint 保存 |
| `DynamicInterleaveCallBack` | `on_epoch_begin` | 根据上一轮各数据集的 eval loss，用 softmax 重新计算采样概率 |
| `PredictInTrainingCallback` | `on_evaluate` | 在评估阶段执行生成式预测（支持左 padding 模式切换） |
| `CustomEarlyStoppingCallback` | `on_evaluate` | 自定义早停策略 |
| `SaveReftCallback` | `on_save` | ReFT 模型的 intervention 保存 |

#### 3.7 ODPS/AiLake 数据源集成

在 `data/loader.py` 和 `data/aligner.py` 中增加了对 `odps://` 和 `ailake://` 前缀的数据路径识别和加载支持，使训练可以直接读取阿里内部数据平台的数据。

#### 3.8 MDL 平台集成

- `scripts/*.sh` — 封装了 `nebulactl run mdl` 命令，支持一键提交到星云 MDL 平台
- `config.json` — MDL 任务配置（队列、资源、镜像等）
- `tuner.py` 中集成 `ml_tracker`，自动上报训练指标
- `extras/misc.py` 中的 `log_meta_to_openlm()` 上报训练元信息

### 四、与原版 LLaMA-Factory 的差异对比

| 维度 | 原版 LLaMA-Factory | 我们的二次开发 |
|------|-------------------|--------------|
| 训练阶段 | PT/SFT/RM/PPO/DPO/KTO | **+Distill（知识蒸馏）** |
| 损失函数 | 标准 CE Loss | **+IFT Loss（Implicit Future Training）** |
| 序列并行 | 无 | **+Ulysses / Zigzag-Ring** |
| 加速模式 | 无 | **+Turbo（transformers_turbo 集成）** |
| 模型仓库 | HuggingFace Hub | **+MOS（自动上传/下载）** |
| 数据源 | 本地文件/HF Hub | **+ODPS/AiLake** |
| 训练平台 | 本地/通用集群 | **+星云 MDL（一键提交）** |
| 指标上报 | WandB/TensorBoard | **+ML Tracker** |
| Checkpoint | 标准保存 | **+交互式 Checkpoint + MOS 自动上传** |
| 数据采样 | 静态概率 | **+动态数据集交错（基于 eval loss）** |
| 模型合并 | 内置 merge | **+独立 merge 脚本 + MOS 上传** |
| TFLOPs | 无 | **+实时 TFLOPs 计算与上报** |
